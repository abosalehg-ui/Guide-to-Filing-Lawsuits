## 1. نظرة عامة سريعة

صفحة ويب واحدة (Single-file static app) تعرض تصنيفات الدعاوى والإنهاءات والخدمات الإلكترونية في منصة ناجز، مع بحث عربي متسامح، وتوجيه (routing) بالـ hash، ونافذة منبثقة (modal) لتفاصيل كل بند. تُستضاف على GitHub Pages.

- **التقنيات:** HTML5 + CSS3 + JavaScript خام (Vanilla JS) بلا أي إطار أو مكتبة أو خطوة بناء. الاعتماد الخارجي الوحيد خطّا Tajawal و Cairo من Google Fonts.
- **الاختبارات:** `node:test` + `node:vm` بلا اعتماديات، وتشتغل على GitHub Actions (Node 20).
- **الحجم:** 7 ملفات نصية + 3 لقطات شاشة. `index.html` = 1,982 سطر (≈ 1,030 CSS، ≈ 300 HTML، ≈ 150 بيانات، ≈ 490 سكربت). الاختبارات 298 سطر.
- **البيانات:** 319 بندًا قابلًا للبحث (6 تصنيفات دعاوى، 6 مجموعات إنهاءات، 10 مجموعات خدمات)، وتحققت إن ما فيها تكرار.

### 2.1 البنية المعمارية وفصل المسؤوليات — 6/10

الملف الواحد خيار مقبول لدليل ثابت يُفتح أوفلاين، والسكربت مقسّم لمقاطع واضحة (بيانات ← فهرس البحث ← التطبيع ← بنّاءات DOM ← المودال ← التوجيه ← البحث). لكن فيه مشكلتين بنيويتين:

**أ) البطاقات مكتوبة يدويًا في الـ HTML ومنفصلة عن البيانات.** كل تصنيف عنوانه مكتوب مرتين: مرة في البطاقة ومرة في الكائن.

`index.html` — بطاقة في `#lawsuits`:
```html
<button type="button" class="category-card" data-category="general">
    <div class="category-icon icon-green" aria-hidden="true">⚖️</div>
    <h3>الدعاوى العامة</h3>
    <p>الدعاوى المالية، العقارية، المستعجلة، المرورية وغيرها</p>
```
وفي `lawsuitCategories.general`:
```js
title: 'الدعاوى العامة',
description: 'تشمل الدعاوى المالية والعقارية والمستعجلة والمرورية',
```
النتيجة: الوصف في البطاقة يختلف فعلًا عن الوصف داخل الصفحة الفرعية، وأي تعديل للعنوان لازم يصير بمكانين. الاختبارات تتأكد إن المفاتيح متطابقة، لكن ما تتأكد إن العناوين متطابقة.

**الحل:** انقل `icon` و `color` و `cardText` لكل مجموعة داخل البيانات، وابنِ الـ 22 بطاقة بدالة واحدة `renderCards(container, data, attr)`، وخلّ الـ HTML يحتوي الحاويات الفاضية فقط.

**ب) المحتوى القانوني مدفون داخل `<script>`.** معدّ المحتوى (غير مطوّر حسب README) يعدّل مصفوفات JS فيها علامات تنصيص وفواصل، وأي فاصلة ناقصة تكسر الصفحة كلها. **الحل:** انقل البيانات الثلاث لملف `data.js` يُحمَّل بـ `<script src="data.js">` (يشتغل أوفلاين على `file://`، بعكس `fetch` لملف JSON اللي تمنعه الـ CSP الحالية `connect-src 'none'` أصلًا).

### 2.3 التكرار (DRY) و Code Smells — 6/10

**أ) بناء فهرس البحث مكرر ثلاث مرات بنفس الشكل** (`Object.keys(lawsuitCategories)…`, `Object.keys(completionData)…`, `Object.keys(serviceData)…`)، ونفس الشي في حلقات `data-count-for*` الثلاث. يمكن توحيدها بدالة `indexGroup(data, type, subLabel)`.

**ب) CSS ميت (Dead CSS):** هذي القواعد ما لها أي عنصر يستخدمها في الـ HTML أو السكربت:
```css
.service-item { … }        .service-item:hover { … }
.service-item .icon { … }  .service-item span { … }
.tooltip { … }             .tooltip::after { … }   .tooltip:hover::after { … }
--accent-blue: #1565C0;    --accent-orange: #E65100;
```
≈ 55 سطر بلا فايدة. **الحل:** احذفها.

**ج) قاعدة تُكتب ثم تُلغى فورًا:**
```css
.footer a,
.step-content a {
    color: var(--secondary);
}

.step-content a {
    color: var(--primary);
}
```
**الحل:** `.footer a { color: var(--secondary); }` و `.step-content a { color: var(--primary); }` منفصلتين.

### 2.4 معالجة الأخطاء والحالات الحدّية — 5/10

**أ) رابط مثل `#/lawsuits/__proto__` يكسر الصفحة (تحققت منه في Chromium).**

`index.html` — في `applyHash()`:
```js
if (section === 'lawsuits' && category && lawsuitCategories[category]) {
    showSubcategory(category);
```
`lawsuitCategories['__proto__']` يرجّع `Object.prototype` (قيمة truthy)، وبعدها `Object.keys(category.subcategories)` يرمي `TypeError: Cannot convert undefined or null to object`. النتيجة الفعلية: قائمة التصنيفات تختفي، والصفحة الفرعية تظهر فاضية بلا عنوان. نفس الشي مع `constructor` و `toString`. ما فيها خطر أمني (كل الكتابة بـ `textContent`)، لكنها صفحة مكسورة من رابط ممكن ينتشر.

**الحل:** في `applyHash()` و `showSubcategory()`:
```js
if (section === 'lawsuits' && category && Object.hasOwn(lawsuitCategories, category)) {
```
وأضف اختبار يتأكد إن المفاتيح الموروثة ما تُقبل.

**ب) المودال يبقى مفتوح بعد زر الرجوع (تحققت منه).** افتح تصنيف ← افتح دعوى ← اضغط Back في المتصفح: الـ hash يتغير والقسم خلفه يتغير، والمودال باقي فوقه. **الحل:** أول سطر في `applyHash()`: `closeModal();`.

**ج) `applyHash` يشتغل مرتين على كل رجوع،** لأنه مربوط على `popstate` و `hashchange` معًا، والتغيير في الـ hash يطلق الاثنين. ما يكسر شي حاليًا لكنه يضاعف إعادة بناء القائمة. **الحل:** اكتفِ بـ `popstate` (اللي يغطي `pushState` والرجوع)، أو خلّ `hashchange` فقط واستبدل `pushState` بـ `location.hash = hash`.

**د) بلا JavaScript الصفحة نص ميت:** البطاقات تظهر بأعداد فاضية، والضغط ما يسوي شي، وما فيه أي رسالة. **الحل:** `<noscript>` بسطر يوضّح إن الدليل يحتاج JavaScript مع رابط ناجز.

### 2.5 الأداء واستهلاك الموارد — 7/10

319 بند حجم صغير، والـ haystack يتطبّع مرة وحدة عند التحميل (قرار ممتاز). لكن:

**أ) البحث يرسم كل النتائج بكل ضغطة مفتاح بلا حد.** كتابة «ال» تبني **317 زر** مع SVG لكل واحد (قستها). على جوال متوسط هذا ملحوظ، والمشكلة الأكبر إمكانية الوصول (شوف 3.5). **الحل:** اعرض أول 50 نتيجة مع زر «عرض الكل»، وأضف debounce بسيط (150ms) على `input`.

**ب) حمولة الخطوط:** 8 أوزان من خطّين (`Tajawal:300;400;500;700;800` + `Cairo:400;600;700`). الصفحة فعليًا تستخدم أوزان 400/500/600/700 بس. **الحل:** قلّص الرابط لـ `Tajawal:wght@400;500;700&family=Cairo:wght@600;700`.

### 2.6 الاختبارات — 6/10

تحسّن كبير من «لا توجد اختبارات». 28 اختبار، كلها تنجح، وتغطي ثوابت حقيقية (الأعداد مشتقة من البيانات، كل بطاقة لها بيانات والعكس، التطبيع العربي). لكن فيه ثلاث فجوات:

**أ) اختبار تغطية البحث تحصيل حاصل (tautological):**

`tests/guide.test.mjs` — في `search covers every item in every data set`:
```js
// Mirrors the builder in index.html.
const index = [];
for (const cat of Object.values(lawsuitCategories)) { … index.push(item) }
…
assert.equal(index.length, expected);
```
الاختبار يبني الفهرس بنفسه ويقارنه بعدّ يحسبه بنفسه بنفس الطريقة، فما يلمس كود `index.html` أبدًا. لو انحذف بناء `serviceData` من الصفحة، هذا الاختبار ينجح (اللي يمسكها هو اختبار آخر يفحص النص بـ `includes`). **الحل:** استخرج مقطع بناء الفهرس الحقيقي (من `const allSearchableItems` لين `Arabic normalisation`) وشغّله في الـ sandbox، وقارن `allSearchableItems.length` بالعدد المتوقع.

**ب) اختبارات الترميز (markup) فحوص نصية سطحية**، مثل:
```js
assert.ok(html.includes(':focus-visible'), 'no :focus-visible rule');
```
تنجح حتى لو القاعدة داخل تعليق. مقبولة كحارس رخيص، لكن لا تعطي ثقة سلوكية.

**ج) ما فيه أي اختبار سلوكي (DOM):** التوجيه، المودال، فخ التركيز (focus trap)، البحث. كل الأخطاء اللي لقيتها في 2.4 و 3.5 كانت بتنمسك باختبار متصفح واحد. **الحل:** ما يحتاج تكسر مبدأ «بلا اعتماديات» في التطبيق نفسه؛ أضف `devDependency` واحد (Playwright) في `tests/` فقط، مع 4–5 سيناريوهات: رابط مباشر لتصنيف، رابط `__proto__`، Back مع مودال مفتوح، Tab داخل المودال، بحث «احوال».

### 2.7 التوثيق — 8/10

README مفيد فعلًا: بنية المستودع، طريقة الاختبار، الروابط المباشرة، إخلاء المسؤولية، تاريخ آخر مطابقة للمحتوى. والتعليقات داخل الكود من أفضل ما يكون في مشروع بهالحجم.

camelCase موحّد في JS، و kebab-case موحّد في CSS، وأسماء الدوال واضحة (`buildCaseTypeRow`, `openSearchItem`). ملاحظتين بسيطة:

### 3.1 الاتساق البصري — 8/10

متغيرات CSS في `:root` للألوان والظلال والزوايا والانتقالات، وخطّين بأدوار واضحة (Cairo للعناوين، Tajawal للنص)، ونظام بطاقات موحد. الخصم: ألوان الأيقونات الست (`.icon-blue` … `.icon-teal`) أكواد hex مباشرة خارج المتغيرات، وفيه `rgba(27,94,32,…)` مكررة 6 مرات بدل متغير `--primary-rgb`.

### 3.2 سهولة الاستخدام والتنقل — 6/10

التنقل نفسه ممتاز: نقرتين للوصول لأي دعوى، روابط قابلة للمشاركة، زر الرجوع يشتغل، اختصار `/` للبحث. **لكن القيمة الأساسية للدليل ضعيفة:** المودال لكل الـ 200+ دعوى يطلع نفس النص بالحرف، والمتغير الوحيد هو الاسم:

`index.html` — في `showCaseTypeDetails()`:
```js
frag.appendChild(buildList([
    'قم بتسجيل الدخول في نظام ناجز',
    'اختر "الخدمات القضائية" ثم "صحيفة الدعوى"',
    'حدد التصنيف: ' + mainCategory,
    'اختر نوع الدعوى: ' + caseName,
    'أكمل البيانات المطلوبة وأرفق المستندات'
]));
```
و `caseDetails = {}` فاضي عن قصد (والتعليق يبرر ذلك بأمانة: المستندات والمحكمة تحتاج مصدر موثوق). القرار صحيح أخلاقيًا، لكن النتيجة إن الدليل حاليًا **فهرس تصنيفات** أكثر منه **دليل تقديم**. المستخدم اللي يدوّر «وش أرفق في دعوى إخلاء عقار؟» ما يلقى جواب.

**الحل:** ابدأ بأكثر 10–15 دعوى طلبًا (إخلاء عقار، نفقة، حضانة، أجر، مكافأة نهاية خدمة…) وعبّ `caseDetails` لها من مصادر رسمية منشورة (أدلة وزارة العدل، نظام المرافعات، نظام العمل)، مع حقل `source` يظهر في المودال. الكود جاهز يعرضها تلقائيًا.

ملاحظة ثانية: البحث ما ينحفظ في الرابط (`#/search` بس)، فما تقدر تشارك نتيجة بحث. **الحل:** `#/search/<query>` واقرأه في `applyHash()`.

### 3.3 الاستجابة — 8/10

تحققت على عرض 375px: ما فيه تمرير أفقي (`scrollWidth = 375`). الأزرار كلها `min-height: 44px`، وفيه breakpoints عند 768 و 380، وهوامش الـ notch عبر `env(safe-area-inset-*)`. الخصم: `.case-type-number` ينزل لـ 28px على الجوال (عنصر زخرفي فما يضر)، و `.modal` بـ `max-height: 85vh` قد ينقص عن الشاشة مع شريط Safari الديناميكي — `85dvh` أدق.

### 3.4 العربية و RTL — 8/10

شغل نظيف فعلًا: `lang="ar" dir="rtl"`، خصائص منطقية (`inset-inline-start`, `padding-inline-start`, `text-align: start`)، سهم SVG بدل محارف الأسهم المعكوسة، `unicode-bidi: isolate` على التاريخ، تطبيع عربي للهمزات والتاء المربوطة والألف المقصورة والتشكيل (وتحققت إن مدى الـ regex صحيح: U+064B–U+0652 + U+0640)، وصيغ جمع عربية صحيحة في `countLabel` (خدمتان / 5 خدمات / 15 خدمة).

**الخصم — اختصار `/` ما يشتغل على لوحة المفاتيح العربية:**

`index.html` — في معالج `keydown`:
```js
if (e.key === '/' && !modalOverlay.classList.contains('active')) {
```
على التخطيط العربي القياسي، نفس الزر يطلع `ظ`، فـ `e.key !== '/'`، والاختصار الموثّق في README ميت لأغلب جمهور المشروع. **الحل:**
```js
if ((e.key === '/' || e.code === 'Slash') && !modalOverlay.classList.contains('active')) {
```

والأرقام لاتينية (1، 2، 3) في كل مكان — اختيار متسق ومقبول، بس يستاهل تقرير واعي.

### 3.5 إمكانية الوصول — 6/10

تحسن جذري من 2/10: أزرار حقيقية، `:focus-visible`، مودال بـ `role="dialog"` و `aria-modal` وفخ تركيز واسترجاع تركيز، تسمية حقل البحث، `prefers-reduced-motion`. لكن فيه ثلاث مشاكل حقيقية (اثنتين تحققت منها بالمتصفح):

**أ) التركيز يضيع بعد كل تنقّل (تحققت منه).** لما تضغط Enter على بطاقة «الدعاوى العمالية»، البطاقة نفسها تنخفي (`categoriesView.hidden = true`)، فالتركيز يسقط على `<body>`. نفس الشي مع زر «العودة للتصنيفات» اللي يخفي نفسه، ومع تبويبات الأقسام. مستخدم لوحة المفاتيح أو قارئ الشاشة يرجع لأول الصفحة بعد كل نقرة. **الحل:** في `showSubcategory()` اجعل `#subcategory-title` بـ `tabindex="-1"` وسوّ له `.focus()`؛ وفي `showCategories()` لما تجي من زر العودة، رجّع التركيز لبطاقة التصنيف اللي كانت مفتوحة.

**ب) منطقة البحث الحيّة تقرأ القائمة كاملة (تحققت منه).**
```html
<div id="search-results" class="search-results" aria-live="polite"></div>
```
الحاوية كلها `aria-live`، فكتابة «ال» تدفع لقارئ الشاشة ≈ 16,500 حرف (317 نتيجة) مع كل ضغطة. **الحل:** شيل `aria-live` من الحاوية، وحطه على عنصر عداد منفصل فيه «تم العثور على 317 نتيجة» بس.

**ج) تباين نص أبيض على `--primary-light` (#4CAF50) = 2.8:1** — تحت حد WCAG AA (4.5:1). يظهر في `.subcategory-header` (التدرج من `--primary` لـ `--primary-light`، والوصف الأبيض يقع على الطرف الفاتح) وفي طرف الـ header. **الحل:** خلّ نهاية التدرج `#2E7D32` (تباين ≈ 5.1:1) بدل `--primary-light` في الخلفيات اللي عليها نص.

### 3.6 التغذية الراجعة — 7/10

فيه رسائل واضحة («أدخل حرفين على الأقل للبحث»، «لم يتم العثور على نتائج»، عدد النتائج)، وتأثيرات hover و active للمس. الخصم: نتيجة «لم يتم العثور» ما تقترح شي (مثلًا «جرّب كلمة أقصر» أو رابط بحث ناجز)، وادعاء الطباعة غير دقيق: تعليق CSS يقول

```css
/* Print styles — expand every section so the whole guide prints, not
   just the tab that happens to be open. */
```
لكن قوائم الإنهاءات والخدمات ما تنبني إلا داخل المودال، وقائمة الدعاوى الفرعية ما تحتوي إلا آخر تصنيف انفتح. فالمطبوع = بطاقات عناوين بلا محتوى. **الحل:** إما تبني عند `beforeprint` قسم طباعة كامل من البيانات الثلاث، أو تصحح التعليق والاختبار عشان ما يوعدون بشي ما يصير.
